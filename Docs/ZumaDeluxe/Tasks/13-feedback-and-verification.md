# 13 · Обратная связь и проверка паритета

Выполнять по мере готовности механик. Использовать фиксации из 00 для сравнения, а тесты проекта — для регрессий. Релизный рубеж наступает после 11 и 12.

- Показать в HUD шкалу и фазу Zuma, счёт, жизнь, текущий и запасной цвет, режим и ранг. Для цветов и усилений использовать читаемые символы; проверить их на маленьком экране. Пауза и подсказки объясняют смену шара и управление.
- Согласовать звуковые и визуальные сигналы для вставки, матча, каскада, Chain, Gap, монеты, бонусов, порога шкалы, открывающегося черепа, поглощения и зачистки. Проверить, что аудио и анимации отражают подтверждённые события.
- Подготовить короткую трассу для EditMode-тестов правил и игровые PlayMode-проверки со штатным `Initial → Game`. В журнале сценария хранить ID попадания, цепочку начислений, позицию переднего шара, фазу, время и исход.
- Сравнить Windows Steam с PC-сборкой Unity на эталонной спирали, двух трассах и карте с туннелем. Для каждого сценария записать начальное состояние, команды, ожидаемую цель и сторону вставки, траекторию отката, порядок событий, очки и исход. Установить допуск по времени из точности записи и повторных замеров.
- Прогнать те же команды в координатах поля с другим кадрированием. На физическом Android проверить передачу команд касаниями, два пальца, потерю фокуса, разные пропорции, 30/60 FPS, перезапуск и длинную сессию Survival.

**Готово, когда** в проверенных сценариях совпадают цель, сторона вставки, порядок событий, очки и исход. Тайминги укладываются в зафиксированный допуск. Для ещё не измеренных случаев записан статус проверки. При повторе и выходе из попытки не накапливаются шары, эффекты и подписки.
